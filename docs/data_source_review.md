## 3. 데이터 구조 검토

### 3.1 컬럼 구성

원본 데이터에는 9개의 컬럼이 존재한다.

| 컬럼 | 의미 | 자료형 참고 | 결측 건수 |
|---|---|---|---:|
| event_time | 이벤트 발생 시각 | str / datetime 변환 가능 | 0 |
| event_type | 이벤트 종류 | str | 0 |
| product_id | 상품 식별자 | int64 | 0 |
| category_id | 카테고리 식별자 | int64 | 0 |
| category_code | 카테고리 코드 | 문자열 성격 | 20,339,246 |
| brand | 브랜드 | str | 8,757,117 |
| price | 이벤트 기록 가격 | float64 | 0 |
| user_id | 사용자 식별자 | int64 | 0 |
| user_session | 세션 식별자 | str | 4,598 |

자료형은 pandas의 읽기 결과를 참고하였다. 특히 `category_code`는 5행 샘플에서 모두 결측이어서 `float64`로 추론된 사례가 있으므로, 소규모 샘플의 자료형을 전체 데이터의 확정 스키마로 사용하지 않는다.

### 3.2 행 단위(Grain)

한 행은 특정 시점에 특정 사용자·세션·상품과 연결되어 기록된 행동 이벤트 1건으로 잠정 정의한다.

확인된 이벤트 종류는 다음 4개다.

- `view`: 상품 조회
- `cart`: 장바구니 추가
- `remove_from_cart`: 장바구니 제거
- `purchase`: 구매

한 주문에서 여러 상품 이벤트가 발생할 수 있으므로 `purchase` 이벤트 수를 주문 건수와 동일하게 해석하지 않는다.

브랜드가 있는 행만 분석하면 결과에 선택 편향이 발생할 수 있으므로 브랜드 미확인 데이터를 포함하는 방식과 제외하는 방식의 차이를 고려해야 한다.

### 5.2.1 이벤트 유형별 중복 후보

| 이벤트 종류 | 전체 이벤트 수 | 중복 후보 수 | 중복 후보 비율 |

**발견된 사실**

- 전체 중복 후보의 약 89.43%가 `remove_from_cart`에 집중되었다.
- `remove_from_cart` 이벤트의 중복 후보 비율은 약 24.92%였다.

- `view`와 `purchase`의 중복 후보 비율은 상대적으로 낮았다.

**집계 정합성 검증**

이벤트 유형별 중복 후보 수를 월별로 합산한 결과 기존 `monthly_df`의 `duplicate_candidate_count`와 5개 월 모두 일치하였다.

`assert` 검증에서도 오류가 발생하지 않았다.

이 검증은 분류된 집계 수치가 기존 집계와 일치하는지 확인한 것이며, 중복 후보가 실제 수집 오류임을 증명하지는 않는다.

**업무적 해석**

장바구니 제거 이벤트에 중복 후보가 집중되는 현상이 여러 달에 걸쳐 관찰되었다.

향후 장바구니 제거 행동을 이벤트 횟수로 집계하면 중복 처리 기준에 따라 결과가 크게 달라질 수 있다.

수집 방식이나 기록 구조에 반복적인 특징이 있을 가능성은 있으나 실제 원인은 미확정이다.

**처리 방침**

- 원본 행을 삭제하지 않는다.
- 중복 후보를 실제 오류로 확정하지 않는다.
- 데이터 마트 설계 시 중복 후보를 식별하거나 중복 포함·제외 결과를 비교하는 방안을 검토한다.

**상태: 유형별 분포 검증 완료 / 중복 처리 기준 미확정**

### 5.4 사용자 및 세션 식별자 검사

| 월 | 고유 사용자 수 | 고유 세션 수 | 복수 사용자 연결 세션 수 |

**발견된 사실**

각 월에서 동일한 `user_session` 값이 둘 이상의 `user_id`와 연결되는 사례가 확인되었다.

월별 복수 사용자 연결 세션 수는 22~86개였다.

월별 개수의 합계는 269이지만, 서로 다른 월에 동일 세션 ID가 존재할 수 있으므로 전체 기간의 고유 문제 세션 수를 의미하지 않는다.

또한 월별 고유 사용자 수와 세션 수를 단순 합산하여 5개월 전체 고유값으로 사용할 수 없다.

**업무적 해석**

세션 ID가 반드시 하나의 사용자 ID에만 연결된다는 가정은 일부 데이터에서 성립하지 않는다.

따라서 세션 기반 퍼널과 전환율을 계산할 때 동일 세션에 연결된 사용자 관계를 어떻게 처리할지 정의해야 한다.

세션 공유, 사용자 식별 방식의 변경, 수집 문제 등의 원인은 아직 확인되지 않았다.

**처리 방침**

- 사용자 분석과 세션 분석의 식별 기준을 구분한다.
- 세션 ID의 결측 및 다중 사용자 연결 여부를 품질 검증 항목에 포함한다.
- 전체 기간에 걸친 세션 ID 재사용 여부는 별도 확인 대상으로 둔다.
- 원본 세션 ID는 임의로 수정하지 않는다.

**상태: 월별 식별자 검사 완료 / 전체 기간 연결 규칙 미확정**

### 5.5 날짜 품질 검사

- 날짜 파싱 실패: 0건
- 원본 이벤트 시간대: UTC
- 분석용 날짜 기준: 향후 KPI 설계 단계에서 확정

날짜 파싱 결과는 정상이지만 시간별 수집 누락 여부까지 확인한 것은 아니다.

## 8. 종합 검토 및 최종 판단

### 8.1 주요 확인 결과

5. 중복 후보는 특히 remove_from_cart 이벤트에 집중되었다.
6. 음수 가격은 대부분 구매 이벤트에 나타났고, 월별 소수 상품에서 반복되었다.
